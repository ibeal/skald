# ask-2026-08-20-check — `skald check`: validate a store

## Spec — acceptance criteria

**Context.** This is the slice that pays for itself immediately. There are two known-bad tickets in
the wild today (`pr: — (local stacked commit)`, written days apart by different sessions) and no way
to see them. It is also the "test, not prose" half of the enforcement story: instructions describe
the contract, `check` is what fails when the contract is broken.

**Refined (after intake):**

- `skald check [--fix]` validates every ticket in `$SKALD_STORE` against the store's `.schema.toml`.
- Report, per ticket, every violation — not just the first:
  - unknown frontmatter key
  - missing required key
  - **enum value outside its declared set, including a valid value with decoration appended**
    (`review (pending Ian)`, `— (local stacked commit)`) — this is the case that motivated the tool
  - malformed date
  - `id` not matching the filename
- **Exit non-zero on any violation**, so a pre-commit hook or CI step can gate on it. Exit 0 and
  print nothing when clean.
- `--fix` repairs only what is unambiguously mechanical — trimming whitespace, normalizing a date
  format, aligning `id` to the filename. **It never guesses at an enum value.** `review (pending Ian)`
  is reported, never silently rewritten to `review`, because the qualifier is information and
  discarding it is data loss. The human moves it to the Build log.
- Output names `file:line` so the violation is navigable.
- Document the pre-commit hook invocation in the README; don't install it.

**Explicitly out of scope:**

- Enforcing that agents *use* skald. That's the permission deny, in the parent's rollout.
- Validating prose sections (that the Build log exists, that AC are present). Frontmatter only —
  section-shape rules can come later if they earn it.

**Verification:** run against `dotfiles/agents/tickets` and `ratatoskr/tickets`; it flags exactly the
known-bad `pr` values and nothing else. A deliberately broken fixture exits non-zero. `--fix` on a
decorated enum leaves it untouched and still exits non-zero.
